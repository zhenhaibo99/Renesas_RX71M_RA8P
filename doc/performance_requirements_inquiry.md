# 性能要求确认事项

本文供乙方 BREXA Technology 向甲方株式会社ベリサーブ确认性能数字。日文版，以及可直接发送的日文全文，见 `performance_requirements_inquiry_ja.md`。

不要先问「性能要多高」。先把 PoC 正在用的数字摆出来，请对方对每一项选择：**必须达到**、**目标**，或**本次不做**。没有答复的，按本文暂定值写进要求，不把它当成已经承诺的指标。

同时运行的最坏组合单独确认。各项数字不自动变成「必须同时达到」。没有允许误差和测量条件的数字，不写成验收指标。对方把某一项从暂定值改成「必须」时，只重估那一项的工数。

## 1. 业务串口和 PC

| 编号 | 向客户确认的问题 | 暂定 |
|---|---|---|
| P-01 | 业务口是否就固定为 115200 8N1？要不要更高波特率，或同时保留日志口 115200？ | 115200 8N1 |
| P-02 | 从 PC 发出命令到收到应答，最坏允许多少毫秒？20 ms 轮询是否够？ | 大约 20 ms 内看到命令 |
| P-03 | 状态快照要每秒几次？现在是 PC 约 1 秒问一次，板卡约 500 ms 可主动上报。 | PC 约 1 秒，板卡约 500 ms |
| P-04 | 持续收发时，要保证每秒多少帧、多少字节？这个数字是平均值还是峰值？ | 未定，不承诺吞吐 |
| P-05 | USB-CDC 是要和 UART 同时工作，还是同一套字节的备用通路？枚举完成允许多少秒？ | 后来再做，UART 仍是验收通路 |

## 2. CAN 与 CAN FD

| 编号 | 向客户确认的问题 | 暂定 |
|---|---|---|
| P-06 | 经典 CAN 是否确认 500 kbit/s、11 位 ID？要不要 29 位 ID？ | 500 kbit/s，仅 11 位 ID |
| P-07 | 总线上我们这块板要占多少负载？两路是否同时发？每路每秒几帧、每帧几字节？ | 演示是约 500 ms 一帧、1 字节 |
| P-08 | RX71M 不能做 CAN FD。是否接受「只有 RA8P 做 FD，RX 收到 FD 请求就明确拒绝」？ | 接受这一分工 |
| P-09 | RA8P 的 CAN FD：仲裁段和数据段各是多少 kbit/s？数据最长 8 字节还是 64 字节？ | 未指定 FD 速率；现有发送按经典帧 |
| P-10 | 接收要滤多少个 ID？过滤是验收条件，还是以后再做？ | 计划中有 11 位 ID 过滤，数量未定 |
