# 性能要件の確認事項

本文は、受注者 BREXA Technology が発注者 株式会社ベリサーブへ性能の数値を確認するためのものである。中国語版は `performance_requirements_inquiry.md`。第 10 節は、そのまま送付できる日本語である。

「性能はどの程度か」から入らない。PoC で使っている数値を先に置き、各項目について **必須**、**目標**、**今回は対象外** のいずれかを選んでもらう。回答のない項目は、本文の暫定値を要求へ書き、確約済みの指標にはしない。

同時に動かす最悪の組合せは、別に確認する。項目ごとの数字を、同時達成の条件へは読み替えない。許容誤差と測定条件のない数字は、受入れ指標にしない。暫定値を「必須」へ上げた項目だけ、工数を見積もり直す。

## 1. 業務シリアルと PC

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-01 | 業務口は 115200 8N1 で固定してよいか。より高いボーレートが必要か。ログ口の 115200 は残すか。 | 115200 8N1 |
| P-02 | PC がコマンドを出してから応答が届くまで、最悪何ミリ秒まで許されるか。20 ms 周期のポーリングで足りるか。 | 約 20 ms 以内にコマンドを見る |
| P-03 | 状態のスナップショットは毎秒何回必要か。現行は、PC が約 1 秒に 1 回問い合わせ、基板は約 500 ms で自発通知できる。 | PC は約 1 秒、基板は約 500 ms |
| P-04 | 連続通信で、毎秒何フレーム、何バイトを保証するか。その数字は平均か、ピークか。 | 未定。スループットは確約しない |
| P-05 | USB-CDC は UART と同時に動かすのか、同じバイト列の代替経路なのか。列挙の完了は何秒までか。 | 後続で行う。受入れ経路は UART のまま |

## 2. CAN と CAN FD

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-06 | クラシック CAN は 500 kbit/s、11 ビット ID で確定か。29 ビット ID は必要か。 | 500 kbit/s、11 ビット ID のみ |
| P-07 | この基板がバスに占める負荷は何パーセントか。二チャネルは同時に送るか。各チャネルは毎秒何フレーム、1 フレームは何バイトか。 | デモは約 500 ms に 1 フレーム、1 バイト |
| P-08 | RX71M は CAN FD ができない。RA8P だけが FD を行い、RX は FD 要求を明示的に拒否する、でよいか。 | この分担とする |
| P-09 | RA8P の CAN FD について、アービトレーションとデータ相の速度はそれぞれ何 kbit/s か。データは最長 8 バイトか、64 バイトか。 | FD の速度は未指定。現行の送信はクラシックフレーム |
| P-10 | 受信フィルタは ID を何個までか。フィルタは今回の受入れ条件か、後回しか。 | 11 ビット ID のフィルタを計画に含める。個数は未定 |

## 3. CANlog

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-11 | 連続で何フレーム、何秒を残すか。256 フレーム、満杯なら最古を上書き、電源を切ると消える、で足りるか。 | 256 フレームを RAM に置く。Flash も SD も使わない |
| P-12 | 記録レートは毎秒何フレームで設計するか。送信と受信の両方を同じログに入れるか。 | レートは未定。送受信とも格納する、は計画上の仮定 |
| P-13 | PC 接続後、バッファ全体をページ読みするとき、何秒までか。 | 未定 |

## 4. GPIO、ADC、DAC、PWM

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-14 | 入力 4、出力 4、ADC 2、DAC 1、PWM 4。数はこれで確定か。 | この数とする |
| P-15 | ADC は毎秒何回サンプルするか。12 ビットは必須か。見るのは一回の変換か、平均値か。 | 約 500 ms に 1 回、12 ビット |
| P-16 | PWM は 1 kHz で固定か。より高くするなら最高は何 kHz か。デューティは 0.1% 刻みで足りるか。 | 1 kHz。デューティは 0 から 1000 のパーミル |
| P-17 | DAC の 0、中点、フルスケールで、電圧の許容誤差はいくらか。どの負荷で測るか。 | コード値の単調変化のみ。電圧誤差は未定 |
| P-18 | これらの端子のセトリングやエッジに、何マイクロ秒以内という要求があるか。 | なし |

## 5. SPI、I2C、LIN

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-19 | この三つは、それぞれ一回の転送か、連続ストリームか。連続なら毎秒何バイトか。 | コマンドを一つずつとし、転送は一回 |
| P-20 | I2C 100 kHz、LIN 19200 でよいか。SPI のクロックは何 Hz と規定するか。 | I2C は約 100 kHz、LIN は 19200。SPI クロックは指標にしない |

## 6. Ethernet

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-21 | IPv4、静的アドレス、UDP ポート一つの周期状態パケットだけでよいか。TCP、Web、暗号は必要か。 | 周期 UDP のみ。TCP、Web、TLS は作らない |
| P-22 | 状態パケットの大きさは何バイトか、何ミリ秒ごとに送るか。出てから PC の表示まで、最悪何ミリ秒か。 | 未定 |
| P-23 | 帯域や損失率は必要か。例えば毎秒何パケット、損失は何パーセントまでか。 | 確約しない |
| P-24 | RGMII の PHY が未準備のとき、UDP を既知の制限として記録し、UART の受入れは止めない、でよいか。 | その扱いでよい |

## 7. 同時負荷、期限、ウォッチドッグ

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-25 | 受入れ時の最悪の組合せは何か。例えば UART、CAN 二路、PWM 四路、ADC、UDP を、同時にそれぞれの数字まで満たす必要があるか。 | 同時負荷は規定しない。項目ごとに見る |
| P-26 | 約 20 ms のコマンド応答以外に、より厳しい制御周期があるか。例えば 1 ms 以内に終わらせるループがあるか。 | 1 ms の制御ループはない |
| P-27 | 独立ウォッチドッグは、タスクが 20 ms ごとに更新する。タイムアウトは RX が約 17.5 秒、RA が 16 秒で、その後リセットする。この時間でよいか。 | このタイムアウトとする |
| P-28 | リセット後、何秒以内に再び PING を受け付ける必要があるか。 | 未定。再接続できればよい |

## 8. 判定

| 番号 | 確認する問い | 暫定 |
|---|---|---|
| P-29 | 各数値の許容誤差はいくらか。どの線長、電源、室温で測るか。判定に使う計測器は貴社のどれか。 | 未定の数字は受入れ指標にしない |
| P-30 | これらの数字は常温で一回か。何回繰り返しても通る必要があるか。 | 未定 |

## 9. 回答の頼み方

項目番号ごとに「必須」「目標」「今回は対象外」のいずれかを書き、数字、または「暫定値どおり」を付けて返してもらう。必須へ上げた項目だけ、工数を見積もり直す。

## 10. 送付用の文面

次の文面は、メールまたは会議資料へそのまま使える。暫定値は本文に入れてある。相手は、変える項目だけを指せばよい。

```text
件名：性能要件の確認（暫定値のご確認）

株式会社ベリサーブ 御中

性能の数値は、まだ要求として確定していません。
現行の PoC で使っている値を、下表の暫定値として置きます。
各項目について、次の三つのいずれかをご指定ください。

1. 必須：受入れでこの数字を満たすこと
2. 目標：満たせば望ましいが、今回の受入れ条件にはしない
3. 今回は対象外：この機能またはこの指標は作らない

あわせて、許容誤差、測定条件（線長、電源、室温、使用する計測器）、および平均かピークかを示してください。
ご回答のない項目は暫定値のまま進め、別途の性能確約にはしません。
複数の機能を同時に動かしたときの最悪条件は、P-25 で別に確認します。項目ごとの数字を、そのまま同時達成の条件には読みません。
```
